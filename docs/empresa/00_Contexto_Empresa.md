## 1. Resumen ejecutivo de SokaTechnologies

SokaTechnologies es una empresa B2B en etapa inicial enfocada en desarrollo de software a medida, sitios web corporativos, automatizaciones de flujos de trabajo, integraciones, dashboards, soporte técnico e infraestructura cloud/on-prem.

La empresa busca resolver problemas operativos reales de pequeñas y medianas empresas mediante soluciones tecnológicas simples, seguras, mantenibles y orientadas a resultados. El objetivo no es vender únicamente programación, sino ayudar a los clientes a reducir trabajo manual, disminuir errores, mejorar trazabilidad, aumentar control operativo, proteger información y escalar procesos internos.

Actualmente SokaTechnologies es operada por un único fundador con experiencia técnica sólida en desarrollo de software, infraestructura, análisis de datos y bases de datos. La empresa cuenta con clientes iniciales en República Dominicana y Panamá, además de productos propios en desarrollo que pueden convertirse en activos comerciales repetibles.

La prioridad estratégica es pasar de una operación dependiente del fundador a una empresa B2B confiable, rentable y escalable, con servicios claros, procesos repetibles, portafolio demostrable, ingresos recurrentes y capacidad futura de contratar equipo.

La prioridad comercial inmediata debe ser validar y vender soluciones con alcance claro, especialmente productos y servicios que puedan generar mensualidades de soporte, mantenimiento, hosting, monitoreo o mejora continua.

## 6. Productos y aplicaciones propias

SokaTechnologies cuenta con productos propios en desarrollo que deben tratarse como activos estratégicos. Este documento solo mantiene el contexto general; el alcance completo de cada producto debe vivir en documentos separados.

| Prioridad | Producto | Estado estratégico |
|---|---|---|
| 1 | Portik | Producto principal para validación comercial inmediata |
| 2 | AutoInventario | Producto técnico con potencial B2B, pendiente de remediación antes de venta |
| 3 | AutoWhatsApp | Herramienta operativa controlada, con límites de consentimiento y cumplimiento |

### 6.1 Portik

Portik es una plataforma web orientada a la operación de portería, control de acceso, administración básica y autogestión de residentes en condominios, conjuntos residenciales o comunidades cerradas.

Portik debe ser la prioridad comercial inmediata de SokaTechnologies porque tiene un mercado identificable, dolor operativo claro y potencial de ingreso recurrente mensual por conjunto o por administradora.

Objetivos iniciales:

- Preparar demo comercial con datos ficticios.
- Validar el producto con administradores reales.
- Conseguir conversaciones de diagnóstico con conjuntos residenciales.
- Cerrar un piloto pagado o semi-pagado.
- Definir modelo de precio por conjunto, unidad o plan mensual.
- Crear caso de éxito anonimizado.
- Establecer soporte y mantenimiento recurrente.

### 6.2 AutoInventario

AutoInventario es una solución técnica para inventario automático de activos Windows, enfocada en recopilar información de equipos, cifrar el payload, enviarlo a un Webhook y sincronizarlo con herramientas ITSM como ManageEngine ServiceDesk Plus.

AutoInventario no debe describirse como inventario comercial de productos, almacenes o mercancía. Su alcance correcto es inventario de infraestructura tecnológica y activos de TI.

Estado estratégico:

- Tiene potencial B2B para empresas con infraestructura Windows y necesidades de auditoría de activos.
- No debe venderse como producto listo hasta completar una fase de estabilización técnica y seguridad.
- Debe orientarse a empresas con soporte IT, auditoría, infraestructura interna o uso de ManageEngine.

### 6.3 AutoWhatsApp

AutoWhatsApp es una herramienta Windows para programar envíos por WhatsApp Web desde Excel, con soporte para preparación manual de sesiones, múltiples líneas, fallback y conversión opcional de texto a audio.

AutoWhatsApp debe manejarse con límites estrictos de consentimiento, cumplimiento y uso aceptable. No debe venderse como herramienta de spam, campañas masivas, scraping, evasión de límites, cobranzas agresivas, juegos de azar o loterías.

Usos permitidos:

- Recordatorios operativos con consentimiento.
- Confirmaciones de citas.
- Notificaciones de servicio a contactos existentes.
- Comunicaciones internas o de bajo volumen.
- Mensajes a contactos propios con autorización verificable.

Usos no permitidos:

- Spam.
- Bases compradas.
- Scraping de números.
- Bypass de límites.
- Campañas masivas no solicitadas.
- Loterías, apuestas o juegos de azar.
- Cobranzas agresivas sin revisión legal.
- Mensajes a contactos sin consentimiento.

- Mantener contexto separado por cliente.

- Documentar decisiones importantes por escrito.

## 14. Reglas técnicas iniciales

Todo proyecto técnico de SokaTechnologies debe priorizar simplicidad, seguridad, mantenibilidad y documentación.

### 14.1 Antes de construir

Antes de iniciar desarrollo, se debe definir:

- Problema de negocio.
- Usuarios.
- Roles y permisos.
- Flujo actual.
- Flujo propuesto.
- Datos involucrados.
- Integraciones necesarias.
- Reglas de negocio.
- Entregables.
- Exclusiones.
- Criterios de aceptación.
- Restricciones técnicas.
- Ambiente de despliegue.
- Requisitos de backup.
- Requisitos de seguridad.

### 14.2 Durante el desarrollo

Cada proyecto debe tener:

- Repositorio Git.
- Ramas o flujo de trabajo definido.
- Commits claros.
- README.
- `.env.example` sin secretos.
- Variables de entorno documentadas.
- Estructura de carpetas comprensible.
- Manejo de errores.
- Validaciones básicas.
- Logs razonables.
- Pruebas básicas cuando aplique.
- Separación entre desarrollo y producción.
- Revisión antes de despliegue.

### 14.3 Antes de producción

Antes de enviar un sistema a producción se debe verificar:

- Backup previo.
- Variables de entorno correctas.
- Credenciales protegidas.
- Migraciones revisadas.
- Pruebas mínimas ejecutadas.
- Accesos configurados.
- Logs revisables.
- Documentación actualizada.
- Plan de rollback cuando aplique.
- Confirmación del cliente para la salida a producción.

### 14.4 Después de producción

Después del despliegue se debe entregar:

- Resumen de lo implementado.
- Instrucciones de uso.
- Accesos acordados.
- Documentación básica.
- Recomendaciones de mantenimiento.
- Plan de soporte.
- Lista de mejoras futuras.

### 14.5 Reglas técnicas para la web pública

La web pública inicial de SokaTechnologies será WordPress en cPanel. Por tanto:

- No se debe complicar la primera versión con un frontend custom si no es necesario.
- No se debe guardar una instalación completa de WordPress en Git.
- El repositorio `sokatechnologies-website` debe contener documentación, assets, tema hijo, snippets y checklists.
- No deben subirse credenciales de cPanel, WordPress, base de datos, SMTP, plugins premium ni backups con datos reales.
- Cualquier configuración sensible debe mantenerse fuera del repositorio.
- La web debe tener páginas mínimas de servicios, portafolio, casos de éxito anonimizados, blog inicial y formulario de contacto.
