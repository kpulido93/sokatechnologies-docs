## 1. Resumen ejecutivo

AutoWhatsApp es una herramienta Windows para programar envíos por WhatsApp Web desde archivos Excel, orientada únicamente a comunicaciones operativas consentidas, controladas y de bajo volumen.

AutoWhatsApp no debe venderse ni presentarse como herramienta de spam, scraping, campañas masivas, evasión de límites de plataforma, captación de jugadores, loterías, apuestas o cobranzas agresivas.

La posición recomendada para SokaTechnologies es:

> AutoWhatsApp puede usarse solo como herramienta operativa controlada para contactos propios, con consentimiento verificable, opción de opt-out y límites claros de volumen, frecuencia y propósito.

Si un caso de uso requiere alto volumen, campañas comerciales formales, trazabilidad avanzada, cumplimiento regulatorio estricto o operación empresarial sostenida, debe evaluarse WhatsApp Business API o un proveedor autorizado, no automatización sobre WhatsApp Web.

---

## 2. Qué es AutoWhatsApp

AutoWhatsApp es una herramienta de apoyo operativo que permite preparar y programar mensajes desde una fuente estructurada, como un archivo Excel, para enviarlos mediante WhatsApp Web bajo control humano.

Debe entenderse como:

- Aplicación Windows de escritorio.
- Herramienta para comunicaciones operativas controladas.
- Flujo basado en archivo Excel preparado por el usuario.
- Apoyo para recordatorios, confirmaciones o notificaciones permitidas.
- Utilidad de bajo volumen, no plataforma de marketing masivo.
- Herramienta que requiere revisión humana y responsabilidad del usuario.

Ejemplos de datos esperados en una plantilla genérica:

- Identificador interno del contacto.
- Nombre genérico o referencia operativa.
- Teléfono autorizado.
- Mensaje aprobado.
- Fecha u hora programada.
- Estado de envío.
- Observación o motivo operativo.

No se deben documentar ni almacenar en este repositorio bases reales, teléfonos reales, mensajes reales, audios reales, sesiones, cookies, tokens ni archivos Excel con datos sensibles.

## 3. Uso permitido

AutoWhatsApp solo debe usarse cuando exista consentimiento verificable y propósito operativo legítimo.

Usos permitidos:

| Uso | Condición |
|---|---|
| Recordatorios de citas. | El destinatario solicitó o aceptó recibir recordatorios. |
| Confirmaciones de servicio. | Existe relación previa y el mensaje es relevante para el servicio. |
| Notificaciones operativas. | El contacto pertenece a una base propia autorizada. |
| Comunicaciones internas. | Los participantes pertenecen a la organización y conocen el canal. |
| Seguimientos de bajo volumen. | Hay relación previa, propósito claro y opción de no recibir más mensajes. |
| Avisos administrativos permitidos. | El mensaje es necesario, proporcional y esperado por el destinatario. |

Buenas prácticas:

- Usar mensajes breves y claros.
- Enviar solo información necesaria.
- Evitar horarios invasivos.
- Mantener registro de consentimiento.
- Respetar solicitudes de baja.
- Hacer pruebas con pocos contactos ficticios antes de cualquier uso real.
- Validar cumplimiento legal y de plataforma cuando aplique.

---

## 4. Uso no permitido

AutoWhatsApp no debe usarse para:

- Spam.
- Campañas masivas no solicitadas.
- Bases compradas.
- Scraping de números.
- Extracción automatizada de contactos.
- Mensajes a personas sin consentimiento.
- Evasión de límites de WhatsApp o WhatsApp Web.
- Bypass de bloqueos, restricciones o controles de plataforma.
- Loterías.
- Apuestas.
- Juegos de azar.
- Captación de jugadores.
- Promoción de participación en actividades reguladas.
- Cobranzas agresivas.
- Amenazas, presión indebida o acoso.
- Mensajes engañosos.
- Suplantación de identidad.
- Envío de contenido sensible sin autorización.
- Comunicación con menores sobre actividades restringidas.
- Reventa como plataforma SaaS de alto volumen sin revisión legal, técnica y de plataforma.

Regla de rechazo:

> Si el prospecto busca enviar mensajes a personas que no dieron consentimiento, usar bases compradas, hacer scraping, promover apuestas/loterías, captar jugadores o automatizar cobranzas agresivas, SokaTechnologies debe rechazar el caso.

## 7. Requisitos de consentimiento

Antes de usar AutoWhatsApp con contactos reales, debe existir consentimiento verificable.

Consentimiento aceptable:

- El contacto solicitó el servicio.
- El contacto autorizó comunicaciones por WhatsApp.
- Existe relación previa y el mensaje es esperado.
- El cliente conserva evidencia de autorización.
- El destinatario puede dejar de recibir mensajes.

Consentimiento no aceptable:

- Número obtenido por scraping.
- Número comprado en una base.
- Número copiado de internet.
- Contacto referido sin autorización propia.
- Participante agregado desde grupos sin permiso.
- Datos antiguos sin validación de permiso.

Checklist de consentimiento:

```text
[ ] La base de contactos pertenece al cliente.
[ ] Existe consentimiento verificable.
[ ] El propósito del mensaje fue informado.
[ ] El mensaje es relevante para la relación existente.
[ ] Existe opción de opt-out.
[ ] Se respeta cualquier baja previa.
[ ] No se usan bases compradas.
[ ] No se usan números scrapeados.
[ ] No se contactan personas sin relación previa.
[ ] Se validó si aplica revisión legal, privacidad o cumplimiento.
```

Si el cliente no puede demostrar consentimiento, no debe usarse AutoWhatsApp.

## 8. Reglas de opt-out

AutoWhatsApp debe respetar solicitudes de baja o no contacto.

Reglas mínimas:

- Todo destinatario debe poder pedir no recibir más mensajes.
- Las bajas deben registrarse antes de nuevos envíos.
- Los números con opt-out deben excluirse de futuras corridas.
- El cliente debe revisar la lista de exclusión antes de enviar.
- No se debe insistir a un contacto que pidió baja.
- No se debe cambiar de línea para contactar a una persona que pidió baja.

Palabras o señales de baja que deben tratarse como opt-out:

- "No enviar más".
- "Dar de baja".
- "Cancelar".
- "No quiero recibir mensajes".
- "Stop".
- Solicitud escrita equivalente.

Checklist de opt-out:

```text
[ ] Existe lista de opt-out o bloqueados.
[ ] La lista se revisa antes de cada corrida.
[ ] Los contactos con baja se omiten.
[ ] El reporte final muestra omitidos por opt-out.
[ ] El cliente entiende que no debe recontactar desde otra línea.
[ ] Las bajas se conservan de forma segura y limitada.
```

## 9. Seguridad y manejo de datos

AutoWhatsApp puede manejar teléfonos, mensajes, archivos Excel, audios generados y sesiones de navegador. Esa información debe tratarse como sensible.

Reglas de seguridad:

- No guardar archivos Excel reales en repositorios.
- No subir bases de teléfonos al repositorio.
- No incluir números reales en documentación.
- No incluir mensajes reales de clientes en ejemplos públicos.
- No versionar sesiones, cookies ni perfiles de navegador.
- No guardar tokens ni credenciales en Git.
- No incluir audios reales en documentación o repositorios.
- No compartir capturas con teléfonos, nombres o mensajes reales.
- No usar datos reales en demos públicas.
- Anonimizar cualquier evidencia antes de documentarla.
- Limitar acceso a archivos de contactos.
- Eliminar archivos temporales cuando ya no sean necesarios.
- Proteger cualquier integración externa, por ejemplo servicios de texto a audio.

Archivos o datos prohibidos en este repositorio:

- Bases reales de contactos.
- Archivos Excel con teléfonos reales.
- Audios generados con contenido real.
- Cookies.
- Sesiones de navegador.
- Tokens.
- Credenciales.
- Capturas con datos personales.
- Reportes con números reales.

Recomendación operativa:

> Para cualquier uso con datos reales, crear una carpeta de trabajo local no versionada, con acceso limitado, retención definida y eliminación posterior cuando ya no sea necesaria.

## 10. Alcance funcional permitido

El alcance funcional permitido debe mantenerse limitado y controlado.

Puede incluir:

| Función | Condición |
|---|---|
| Carga de Excel | Solo archivos autorizados, no versionados y protegidos. |
| Validación de columnas | Verificar teléfono, mensaje, fecha y campos necesarios. |
| Vista previa | Revisar mensajes antes de enviar. |
| Programación de envío | Usar horarios razonables y bajo volumen. |
| Envío manual o supervisado | El usuario mantiene control de la corrida. |
| Gestión local de líneas | Solo líneas autorizadas por el cliente. |
| Pausas entre mensajes | Reducir riesgo operativo y abuso. |
| Límite por corrida | Evitar uso masivo o invasivo. |
| Registro de resultado | Enviados, fallidos, omitidos y opt-out. |
| Lista de opt-out | Excluir contactos que pidieron baja. |
| Modo prueba | Validar con pocos contactos ficticios o autorizados. |
| Conversión texto a audio | Solo si el contenido está autorizado y no contiene información sensible innecesaria. |

No debe incluir:

- Scraping.
- Enriquecimiento de bases.
- Compra/importación de bases externas.
- Bypass de límites.
- Ocultamiento de identidad.
- Cambio automático de líneas para insistir a contactos.
- Envío masivo sin supervisión.
- Automatización para evadir bloqueos.
- Chatbot comercial completo.
- CRM completo.
- SaaS multi-cliente de alto volumen sin revisión formal.

## 11. Límites comerciales

AutoWhatsApp debe posicionarse con cautela.

Posicionamiento permitido:

> Herramienta operativa controlada para recordatorios, confirmaciones y comunicaciones permitidas con contactos propios y consentimiento verificable.

Posicionamiento no permitido:

- "Herramienta para enviar mensajes masivos".
- "Sistema para conseguir clientes por WhatsApp".
- "Automatización para contactar bases compradas".
- "Bot para evitar bloqueos".
- "Solución para apuestas, loterías o captación".
- "Sistema automático de cobranza agresiva".

Reglas comerciales:

- No vender por volumen de mensajes como incentivo principal.
- No ofrecer resultados garantizados de ventas o recuperación.
- No ofrecer evasión de límites o bloqueos.
- No aceptar clientes sin consentimiento verificable.
- No aceptar usos legalmente sensibles sin revisión especializada.
- No presentar AutoWhatsApp como reemplazo empresarial de WhatsApp Business API.
- Para alto volumen o comunicación formal, recomendar proveedor autorizado o API oficial.
- Incluir soporte limitado, alcance escrito y responsabilidades del cliente.
- Incluir validación legal, privacidad y cumplimiento cuando aplique.

Responsabilidades del cliente:

- Garantizar origen legítimo de la base.
- Mantener evidencia de consentimiento.
- Respetar opt-out.
- Revisar contenido antes de enviar.
- No usar la herramienta para usos prohibidos.
- Proteger archivos y resultados.
- Validar cumplimiento legal aplicable.
