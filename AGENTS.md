# AGENTS.md

## Rol de Codex

Actúa como asistente para mantener documentación interna clara, práctica y accionable para SokaTechnologies.

## Objetivo del repositorio

Centralizar procesos, estándares, plantillas y documentación operativa para una empresa pequeña de software B2B que busca crecer.

## Reglas obligatorias

- No incluir secretos, credenciales ni tokens.
- No incluir datos confidenciales de clientes.
- No mezclar información entre clientes.
- Usar nombres genéricos en ejemplos públicos.
- No crear documentos largos sin estructura accionable.
- Preferir checklists, tablas, pasos y plantillas.
- Mantener el tono profesional, claro y práctico.
- Documentar procesos que ayuden a vender, entregar y mantener proyectos.
- Recomendar validación legal, fiscal o contable cuando aplique.

## Principios de edición

- Priorizar utilidad operativa sobre explicación teórica.
- Mantener cada documento enfocado en una decisión, proceso o plantilla concreta.
- Preferir listas de verificación, tablas, criterios y pasos secuenciales.
- Reutilizar documentos existentes antes de crear variantes nuevas.
- Aclarar supuestos cuando falte contexto operativo.

## Antes de modificar documentos

Codex debe presentar:

1. Documento a modificar.
2. Objetivo del cambio.
3. Estructura propuesta.
4. Riesgos de confidencialidad.

## Formato recomendado

- `Objetivo`: para que sirve el documento.
- `Cuando usarlo`: en que momento aplica.
- `Pasos` o `Checklist`: como ejecutarlo.
- `Plantilla` o `Tabla`: si el documento requiere entradas repetibles.
- `Notas y limites`: si hay exclusiones, dependencias o validaciones externas.

## Criterios mínimos

- Documento claro y accionable.
- Sin información sensible.
- Formato consistente.
- Útil para operación real de SokaTechnologies.

## Entrega esperada de Codex

Al terminar un cambio documental, Codex debe resumir:

1. Archivos creados o modificados.
2. Proposito de las carpetas afectadas.
3. Riesgos de confidencialidad considerados.
4. Siguientes documentos o mejoras recomendadas.
